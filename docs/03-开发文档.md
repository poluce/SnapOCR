## 0. 开发环境与构建

### 0.1 环境要求

- Windows 10 1903+ / Windows 11，x64；
- Qt 6.11.1 `msvc2022_64`（本机默认 `E:\Qt6\6.11.1\msvc2022_64`，可用 `QTDIR` 覆盖）；
- Visual Studio 2022 或 2026，安装“使用 C++ 的桌面开发”工作负载（本机 VS 18 / MSVC 19.51）；
- CMake ≥ 3.21、Ninja（本机默认取 Qt 自带 `Tools/CMake_64`、`Tools/Ninja`）；
- Windows SDK 10.0.26100（含 C++/WinRT 头文件）；
- CI 使用 Qt 6.10.3（aqtinstall 3.3.0 尚不支持 Qt 6.11 新仓库布局），源码保持 Qt 6.5+ 兼容。

工具链实测：MSVC 19.51（v145）+ Qt 6.11.1 msvc2022_64 编译/链接、真实 `windows` 平台冒烟、ctest 均通过。

### 0.2 构建与运行

```bat
:: Debug 构建 + ctest（单测 / offscreen 冒烟）
scripts\build.bat

:: Release 构建（跳过测试）
scripts\build.bat Release --no-tests

:: 启动 GUI（Qt 运行库自动加入 PATH）
scripts\run.bat

:: CLI 自检
build\SnapOCR.exe --version
build\SnapOCR.exe --smoke-test
ctest --test-dir build --output-on-failure
```

WSL 下调用 Windows 工具链：

```bash
cmd.exe /c 'cd /d D:\Document\SnapOCR && scripts\build.bat Debug'
```

构建产物在 `build/`（`.gitignore` 已忽略）；`scripts/build.bat` 负责定位 vcvars64、Qt、CMake、Ninja，再 configure/build/test。

### 0.3 仓库结构与代码地图

```text
SnapOCR/
├── CMakeLists.txt              # 顶层工程（snapocr_core / SnapOCR / tests）
├── cmake/Version.h.in          # 版本注入模板
├── scripts/                    # build.bat / run.bat
├── docs/                       # 四份文档 + assets
├── src/
│   ├── main.cpp                # 入口：控制台挂接 + QApplication + Application
│   ├── app/                    # 应用控制器（后续：托盘/热键/单实例）
│   ├── capture/                # 屏幕捕获（M1）
│   ├── overlay/                # 逐屏覆盖层与选区（M1）
│   ├── editor/ annotate/       # 标注编辑器与文档模型（M2）
│   ├── ocr/                    # OCR 引擎抽象与实现（M3/P1）
│   ├── ui/                     # 主窗口、设置、结果窗、工具条
│   ├── platform/win32/         # 热键/DPI/剪贴板/自启/控制台/捕获
│   └── common/                 # 配置、日志、几何工具
├── tests/                      # Qt Test 单测
└── .github/workflows/build.yml # Windows CI
```

依赖方向：业务模型（capture/annotate/ocr）不依赖窗口类；UI 不直接调 Win32 捕获/热键 API；OCR 业务不得直接 `#include <winrt/...>`；跨模块传值类型/信号；坐标以物理像素为权威。详见 [设计文档](02-设计文档.md)。

### 0.4 打包与发布

- `windeployqt --release --compiler-runtime --no-opengl-sw --translations zh_CN` 部署到 `dist/SnapOCR/`；
- 绿色包 zip：Qt DLL + `platforms/qwindows.dll` + `imageformats/` + `styles/` + `translations/` + `SnapOCR.exe`；
- 安装包（Inno Setup）/代码签名/自动更新为 P2；
- 打包目标、结构与依赖许可证见 [设计文档 §11/§14](02-设计文档.md)。

### 0.5 CI

GitHub Actions `windows-latest`，步骤：安装 Qt → 初始化 MSVC → CMake+Ninja Release 构建 → `ctest` → 原生 `windows` 平台 `--smoke-test`。

- 工作流文件：`.github/workflows/build.yml`；
- CI 固定 Qt 6.10.3（aqtinstall 兼容性），本机 6.11.1；待 aqt 支持 6.11 后统一；
- CI 必须全绿才合并；最近成功运行见 [完成情况](04-完成情况.md)。

## 8. 并行分工（M1 起，Agent Teams）

共享契约先由 Lead 定稿（`CaptureResult`、`SelectionModel`、`AnnotationDocument`、`IOcrEngine`、`Settings`），再分线并行：

| 线 | 写域（workspace 相对） | 职责 | 依赖 |
|----|------------------------|------|------|
| A 捕获/覆盖层 | `src/capture/`、`src/overlay/`、`src/platform/win32/` | 显示器枚举、GDI 捕获、逐屏覆盖层、选区交互、DPI 换算 | 契约 |
| B 标注/编辑器 | `src/annotate/`、`src/editor/` | 图元模型、画布渲染、工具、撤销重做、导出 | 契约 + A 的选区结果 |
| C OCR | `src/ocr/` | 引擎抽象、Windows OCR、切片、结果整理、基准工具 | 契约（可与 A/B 并行） |
| D 系统/测试/CI | `src/app/`、`src/ui/`、`tests/`、`scripts/`、`.github/` | 热键/托盘/设置/单实例/自启、单测与手测清单、CI | A/B/C 接口 |

协作规则：写域不重叠；跨线接口改动先改设计文档并通知所有写者；集成分支由 Lead 统一构建与评审；每日合并前跑 `scripts\build.bat` + `ctest`。

## 10. 开发规范

### 10.1 语言与编码

- 文档、注释、提交说明使用**简体中文**；代码标识符、文件名、Git 分支使用英文。
- 源码编码 UTF-8，无 BOM；源码中**直接写汉字**，禁止用 `\uXXXX` 转义 CJK。
- MSVC 统一 `/utf-8`；CMake 已为所有目标加该选项，新增目标必须复用 `snapocr_set_common_options`。
- 换行：仓库内 LF；`.bat/.cmd/.ps1` 由 `.gitattributes` 固定为 CRLF。

### 10.2 分支与提交

- 主分支 `main` 保持可构建、测试通过；功能/修复用短生命周期分支：
  `feature/m1-capture`、`fix/dpi-offset`、`docs/ocr-benchmark`。
- 提交信息遵循 **Conventional Commits**：

  ```text
  <type>(<scope>): <中文简述>

  <可选正文：为什么、影响范围、验证方式>
  ```

  常用 type：`feat` `fix` `docs` `refactor` `test` `build` `chore` `perf` `style`；
  常用 scope：`capture` `overlay` `editor` `annotate` `ocr` `platform` `app` `ui` `tests` `ci` `docs`。
- 一次提交聚焦一件事；格式化/重命名等纯机械改动单独提交。
- **提交需用户明确要求**；Agent 协作时不得擅自 `git add`/`commit`/`push` 工作区修改（详见 `AGENTS.md`）。
- 禁止提交构建产物、日志、模型临时文件、个人配置（见 `.gitignore`）。

### 10.3 构建与验证

提交前必须：

1. `scripts\build.bat`（Debug，含 ctest）通过；或至少 `scripts\build.bat Release --no-tests` + 相关单测。
2. 涉及 UI/截图的改动，附真实 Windows 平台的启动/截图验证说明（WSL 下可用 `cmd.exe /c ...` 调 Windows 工具链）。
3. 新增/修改行为时更新对应文档（需求编号、设计文档、完成情况）。

```bash
cmd.exe /c 'cd /d D:\Document\SnapOCR && scripts\build.bat Debug'
```

### 10.4 代码风格

- 以仓库根 `.clang-format` 为准（4 空格、100 列、Allman 大括号）；新文件先格式化再提交。
- 命名：
  - 类/结构体/枚举 `PascalCase`，函数 `camelCase`，成员 `m_camelCase`，常量 `kPascalCase`；
  - 文件名与主要类同名（`MainWindow.h/.cpp`）；
  - 命名空间 `snapocr::<模块>`。
- C++20：优先 `std::optional`/`enum class`/RAII；禁止裸 `new/delete`（Qt 父子对象除外）；禁止异常跨 Qt 信号槽边界。
- Qt：
  - 对象尽量用父对象管理生命周期；非 QObject 用 `std::unique_ptr`；
  - 字符串用 `QStringLiteral` / `QString::fromUtf8`，UI 文本一律 `tr()`；
  - 信号槽连接使用函数指针语法（编译期检查）；
  - 不在主线程做 >16ms 的阻塞操作（捕获、OCR、磁盘大文件）。
- Windows：
  - Win32 API 统一封装在 `src/platform/win32/`，返回错误码/临时错误消息，不抛异常；
  - 坐标以**物理像素**为权威（见设计文档 §4），UI 边界处才换算；
  - 句柄/DC/HWND 使用 RAII 包装，禁止泄漏。
- 注释解释“为什么/约束”，不重复代码字面；复杂算法给出公式或示意。

### 10.5 错误处理与日志

- 用户可见错误：中文、可理解、给出下一步（如“热键被占用，请在设置中更换”）；禁止把原始 Win32 错误码直接甩给用户。
- 内部错误：`qCWarning`/`qCCritical` + 日志文件；日志按模块分类（`snapocr.capture`、`snapocr.ocr` 等）。
- 日志中**禁止**记录 OCR 识别原文、剪贴板内容、用户截图路径中的敏感信息（隐私）。
- 所有失败路径必须有单测或手测覆盖，不允许静默失败。

### 10.6 测试

- 新核心逻辑（坐标换算、选区模型、撤销重做、结果整理、配置）必须配 Qt Test 单测。
- 渲染类改动补黄金图像测试（`tests/data/golden/`），使用像素哈希/容差比较。
- 修 bug 先补回归测试，再修。
- 手测清单（多屏/DPI/热键/托盘）在本文档对应里程碑与完成情况中维护，发版前逐项勾选。
- CI 必须绿；本地 `ctest --test-dir build --output-on-failure` 必须通过。
