## 3.6 文字标注行为修正（2026-10-23）

要求的语义：点击位置打开输入框；有输入则成为文字图元；**没有输入就换位置时，空输入框必须消失**。

修复了 3 个叠加缺陷：

| # | 缺陷 | 影响 | 修复 |
|---|------|------|------|
| 1 | 工具条不接收焦点后，点工具条不会让输入框失焦 | 空输入框一直留在画布上，切换工具也不消失 | 所有工具条动作（切工具/颜色/线宽/撤销/重做/复制/保存/取字）前调用 `commitOrDiscardTextInput()`：有内容提交，无内容丢弃 |
| 2 | 旧输入框 `deleteLater` 的 `destroyed` 回调无条件把 `m_textEditor` 置空 | 新输入框变成“野控件”：还显示着但已不受管理，无法提交，残留成空标注 | 回调里校验指针身份，只有当前输入框销毁时才置空 |
| 3 | `deleteLater` 之前子控件仍可拦截鼠标 | 提交/丢弃后立刻点击画布，点击被已隐藏但未销毁的输入框吃掉 | 销毁前先 `hide()` + `setEnabled(false)` |

回归测试（`test_annotation_canvas`，13 条用例）：
- `emptyTextInputLeavesNoItem`：空输入不产生图元
- `typedTextInputCommitsOneItem`：输入内容提交为一个 Text 图元
- `clickingNewPositionDiscardsEmptyTextInput`：空输入换位置后不残留

已知未覆盖（阶段二/三范围）：
- 修改已选中图元的颜色/线宽（当前颜色线宽只作用于新图元）
- 工具快捷键（1–9）、双击工具恢复默认样式
- 取字按钮始终对原图识别（不含标注），符合预期但需在文档说明

## 3.36 阶段三进展：在线更新（F-SYS-16，2026-10-26）

**需求**：有新版本发布 → 提示更新 → 用户点击更新 → 下载 → 安装 → 提示安装完成并重启应用。

| 环节 | 实现 |

## 3.22 阶段三进展：性能验收实测（2026-10-26）

新增 `--perf-selftest`（捕获/裁剪/OCR 端到端/空闲内存），并用 `WM_HOTKEY` 投递测热键延迟。

| 指标 | 目标 | 实测 | 结论 |
|------|------|------|------|
| 热键 → 遮罩显示 | ≤80ms（可接受 ≤150ms） | **67ms** | ✅ |
| 全屏捕获 3840×2160 | ≤150ms | **57ms** | ✅ |
| 区域裁剪 1920×1080 | 可忽略 | **2ms** | ✅ |
| OCR 端到端（1920×1080 合成图，9 行 367 字） | ≤1000ms | **91ms** | ✅ |
| 空闲工作集（托盘） | ≤120MB | **28MB** | ✅ |
| 稳定性 20 轮 | GDI 零增长；句柄 ≤16 / USER ≤10（预热 3 轮后测量） | handles +4…+12 / gdi +0 / user +2…+6 / ws −31MB | ✅ |

说明与边界：
- 测量在**锁屏会话**下完成，捕获/OCR 均正常（GDI 捕获与 Windows OCR 不依赖交互桌面）；
  热键延迟用 `PostThreadMessage(WM_HOTKEY)` 注入到主线程，绕过了物理按键，但走了
  与真实热键相同的 native event filter 路径（差异仅在键盘驱动层）。
- OCR 91ms 是**合成纯文字图**的理想值；真实截图（含图形/复杂背景）会慢一些，
  但仍有充足余量（目标 1000ms）。
- 该自检可随时复现：`SnapOCR.exe --perf-selftest`。

## 3.16 阶段三进展：贴图可再取字/再标注（F-ANN-19 补全，2026-10-26）

追溯审计发现 F-ANN-19 的验收含「可再标注/取字」，此前贴图窗只有复制/保存/缩放/旋转。本轮补齐：

| 入口 | 行为 |
|------|------|
| 右键「提取文字」/ `Ctrl+T` | 贴图直接交给 OCR 流程（无需再框选），结果窗可编辑/复制/重试 |
| 右键「在编辑器中打开」/ `Ctrl+E` | 贴图作为底图进标注编辑器，`Enter` 复制、`Ctrl+S` 保存、`Esc` 关闭；编辑完可再贴/再存 |

实现要点：
- `PinWindow` 新增 `ocrRequested` / `editRequested` 信号与 `requestOcr()`/`requestEdit()`（菜单与快捷键共用，便于单测）
- `Application::openEditorForImage()`：独立于截图覆盖层创建 `EditorWindow` + `AnnotationDocument`，
  按屏幕 DPR 换算逻辑尺寸并以光标为中心定位、夹取到屏幕内；关闭时自动释放文档
- 测试：`test_pin_window` 增加 2 条（两个信号都带原图）
